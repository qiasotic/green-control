# Руководство и контрольные сценарии

Запустите `02_RUN_WINDOWS.bat` и откройте [локальное рабочее место](http://127.0.0.1:8501). При первом запуске используйте `START_HERE_WINDOWS.bat`.

## Три технических примера в отдельной базе

Чтобы не смешивать тестовые дела с рабочими, запустите приложение из PowerShell в папке проекта с отдельным файлом SQLite.

```powershell
$env:GREEN_CONTROL_DB = Join-Path $PWD.Path 'data/green_control_demo.sqlite3'
.\.venv\Scripts\python.exe cli.py import examples/TECHNICAL_SMOKE_3_CASES.csv
.\.venv\Scripts\python.exe -m streamlit run app.py
```

При занятом порте остановите предыдущий экземпляр либо укажите `--server.port 8502`. Значение `GREEN_CONTROL_DB` действует только для процессов, запущенных из этого окна PowerShell.

1. **Рабочее место.** Должны отображаться три дела, одно с отклонениями и одно, требующее уточнения. Нажмите «Контрольное дело № 002» в приоритетной очереди.
2. **Анализ и проверка → R1–R3.** По `DEMO-FLAG-002` ожидается FLAG по всем правилам. Раскройте «Исходные значения», прочитайте условия, основания и дальнейшие действия. В R3 выберите «Запросить сведения», укажите комментарий и сохраните. Дело перейдёт в состояние «Ожидает сведений».
3. **Реестр дел.** Найдите `DEMO-OK-001` и откройте карточку. Ожидается PASS по R1–R3. По `DEMO-NODATA-003` ожидается NEED_DATA по всем трём правилам.
4. **Рассмотрение и заключение.** Откройте карточку, выберите рабочее состояние «Завершено», укажите заключение и основание. Во вкладке «История» появятся переход и заключение.
5. **Редактирование.** Измените предварительную дату закрытого дела и сохраните. Дело вернётся на рассмотрение. В истории можно выбрать предыдущую редакцию и открыть её расчёт. Предыдущее заключение отмечено как историческое.
6. **Отчёты.** Выгрузите отфильтрованный реестр в CSV/XLSX. Выберите дело и скачайте индивидуальное заключение с исходными сведениями, анализом и историей.

## Новое дело без файла

1. В разделе «Новое дело» оставьте предложенный номер или введите свой, выберите «Общая процедура (учебная)», укажите даты заявления 16.11.2026 и выдачи 19.11.2026.
2. Отметьте «Заявление», «Акт обследования» и «Получен полный комплект». Укажите предварительное решение от 18.11.2026.
3. Выберите «Начисление и оплата». Введите 1500 в оба поля. Если сумма неизвестна, оставьте поле пустым.
4. На последнем шаге проверьте сведения, затем выберите «Сохранить и проверить». Ожидаются три PASS. Чтобы проверить черновик, выполните часть шагов и нажмите «Сохранить черновик», затем откройте «Продолжить заполнение» в карточке.
5. Для проверки отклонения можно изменить дату предварительного решения на 20.11.2026. Ожидается R3=FLAG.

## Файловый обмен

В разделе «Импорт из ИС» можно скачать шаблон XLSX, выбрать готовую выгрузку и нажать «Импортировать файл». Для папки `incoming/` положите в неё CSV или XLSX, затем нажмите «Импортировать из папки обмена». Успешный файл перемещается в `incoming/processed/`. При конфликте номеров исправьте файл либо явно разрешите обновление существующих дел. Ошибка в одной записи отменяет сохранение всей выгрузки.

## Проверка выборки и сводного отчёта

1. В отдельной демобазе откройте «Аналитика» и проверьте, что без фильтров отображается 200 дел, из них 80 с FLAG и 70 с NEED_DATA.
2. Установите индикатор R3 и результат FLAG. В исходном наборе ожидается 30 дел. Откройте карточку из очереди, перезапустите анализ и проверьте отметку в истории.
3. Зафиксируйте заключение с комментарием. После возврата к той же выборке количество завершённых дел увеличится на одно. Если затем исправить дату решения, текущее дело изменит свой модельный результат, а прежнее заключение останется в истории.
4. Нажмите «Сформировать сводный отчёт». Скачайте CSV или XLSX. Параметры фильтров, дата формирования, рабочие состояния, R1–R3, помесячные данные и очередь включены в выгрузку. HTML можно открыть в браузере и распечатать в PDF.
5. Откройте индивидуальное заключение. В XLSX проверьте исходные поля, заключение и листы истории. Отчёт испытаний в том же разделе скачивается отдельно.

## Диагностика

- `03_TEST_WINDOWS.bat` запускает автоматические тесты и проверяет три технических примера.
- `python cli.py validate examples/TECHNICAL_SMOKE_3_CASES.csv` проверяет файл без записи в БД.
- Если браузер недоступен, проверка запуска сервера доступна по адресу [проверки состояния](http://127.0.0.1:8501/_stcore/health). Ответ `ok` подтверждает доступность сервера. Для проверки элементов интерфейса откройте главную страницу.
- Рабочая БД по умолчанию находится в `data/green_control.sqlite3`. Резервируйте её при остановленном приложении.
