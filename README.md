# Зелёный контроль · v2.0

Локальный цифровой сервис предварительной проверки разрешительных дел по порубочным билетам. Три индикатора проверяют финансовые условия, комплектность материалов и последовательность дат. Итоговое заключение оформляет специалист. Профиль `DEMO-2026-01` версии `1.0` содержит модельные условия.

## Муниципальная сверка

Для муниципальной проверки подготовьте реестр, опись актов и две накопительные выписки бухгалтерии. Раздел «Импорт из ИС» принимает их на отдельных вкладках. На главном экране выберите этап выдачи, а в карточке откройте «Подготовка и сверка». Учебные файлы находятся в `examples/municipal`. [Формат обмена и SQLite](docs/MUNICIPAL_DATA.md) · [Сценарий защиты и правки для команды](docs/MUNICIPAL_HANDOFF.md).

## Запуск

- Откройте папку `green-control` в Проводнике Windows и дважды нажмите `START_HERE_WINDOWS.bat`. Дождитесь сообщения с адресом сервиса. На первом запуске потребуется Python x64 3.12–3.14. Скрипт установит зависимости и выполнит начальную проверку, поэтому ожидание может быть дольше.
- Если вкладка браузера не открылась, откройте [127.0.0.1:8501](http://127.0.0.1:8501) или адрес из окна запуска. Оставьте это окно открытым на время работы. Для остановки сервиса нажмите Ctrl+C в этом окне.
- macOS/Linux с Python 3.12 или новее. Выполните `bash setup_mac_linux.sh`, затем `bash run_mac_linux.sh`.
- При обновлении сделайте резервную копию существующей `data/green_control.sqlite3` после остановки приложения. Обновите исходники и зависимости, затем запустите сервис. SQLite применит миграции автоматически. Дела, исходные сведения и заключения сохраняются.

## Получение исходных данных

1. **Новое дело.** Введите сведения, выберите подтверждённые документы и финансовый сценарий, сверьте карточку. Для черновика нужны номер и категория. Чтобы завершить ввод нового дела, укажите также дату заявления.
2. **Импорт из ИС.** Загрузите CSV/XLSX или положите выгрузку в `incoming/` и запустите файловый обмен. Ошибка строки отменяет импорт всего файла. Совпадающие дела пропускаются. Чтобы обновить различающиеся дела с теми же номерами, явно разрешите создание новых редакций.
3. **Подключение к GitHub.** Откройте вкладку «Подключение к GitHub» в разделе импорта. Проверьте публичную ссылку, выберите CSV/XLSX, сопоставьте колонки и подтвердите импорт. [Порядок подключения и работы с подсказками](docs/GITHUB_AND_GUIDANCE.md).

В боковой панели включите ползунок «Подсказки по работе с системой», чтобы увидеть пояснения рядом с основными элементами. Нажмите «Зелёный контроль» вверху панели для возврата на главный экран. На главном экране видна цепочка работы, а в карточке — исходные поля, применённое условие и рекомендуемое действие. Даты отображаются в формате ДД.ММ.ГГГГ.

**Рабочее место** показывает показатели и очередь. **Реестр** поддерживает поиск, фильтры и экспорт CSV/XLSX. **Анализ и проверка** содержит объяснения R1–R3, повторный расчёт, рассмотрение, заключение и историю редакций. После изменения данных закрытое дело возвращается на рассмотрение. **Аналитика** агрегирует выбранные дела, позволяет перейти к карточке с сигналом и повторно проверить выборку целиком. **Отчёты** выгружают индивидуальное заключение TXT/XLSX, сводку CSV/XLSX/HTML и результаты испытаний Markdown/JSON. HTML можно распечатать в PDF средствами браузера.

## Видеодемонстрация на 5 минут

Быстрый старт с 200 учебными делами в **отдельной базе**. Откройте PowerShell в распакованном каталоге после установки зависимостей.

```powershell
Copy-Item data/synthetic/green_control_demo.sqlite3 data/green_control_demo_session.sqlite3
$env:GREEN_CONTROL_DB = Join-Path $PWD.Path 'data/green_control_demo_session.sqlite3'
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Команда копирования предполагает свежий сеанс. Если файл сеанса уже существует и содержит нужные отметки, выберите новое имя в обеих строках. До начала записи закройте экземпляр на том же порту либо добавьте `--server.port 8502`.

| Время | Действие |
| --- | --- |
| 0:00–1:10 | Создайте учебное дело вручную. Категория — общая процедура. Заявление 16.11.2026, выдача 19.11.2026. Отметьте заявление и акт, подтвердите комплектность, оставьте дату решения и оплату неизвестными. Сохраните и проверьте. |
| 1:10–2:00 | Откройте R3, покажите NEED_DATA и исходные значения. Зафиксируйте «Запросить сведения» с комментарием. |
| 2:00–3:05 | Внесите предварительное решение от 20.11.2026, сохраните. R3 даст FLAG. Оформите модельное заключение и откройте историю. |
| 3:05–4:10 | В аналитике выберите R3 и FLAG, покажите показатели и месяцы. Можно открыть любое дело из очереди. |
| 4:10–5:00 | Сформируйте сводный XLSX. Скачайте индивидуальный отчёт и покажите результаты испытаний. |

В разделе «Импорт из ИС» можно с подтверждением загрузить три отдельных контрольных сценария или весь набор. Для повторной демонстрации используйте новую копию демонстрационной БД. Удалять можно только собственный файл завершённого демонстрационного сеанса после остановки сервера. Рабочую базу и поставляемый образ сохраняйте.

Интерфейс находится в `app.py` и `ui/`. Модельные правила, история и отчёты находятся в `core/`. Генератор и оценка качества вынесены в `scripts/`. Журнал подписывает действия условным именем «Локальный оператор». Используйте технические и обезличенные сведения. SQLite сериализует записи. Для одновременной работы многих специалистов потребуется серверная БД и ведомственная идентификация. Измерения на синтетике отражают согласованность правил с заданными сценариями. Эффективность в реальной эксплуатации предстоит проверять отдельно.
