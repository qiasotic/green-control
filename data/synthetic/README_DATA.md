# Демонстрационная выборка

| Файл | Содержимое |
| --- | --- |
| `dataset.csv`, `dataset.xlsx` | Один набор из 200 технических дел для импорта двумя способами |
| `ground_truth.csv` | Технический номер, код сценария и заранее назначенные статусы R1, R2, R3 |
| `generation_manifest.json` | Версия генератора, seed, дата среза, объём и распределение по сценариям |
| `invalid_duplicate_id.csv` | Две строки с повторным ID для проверки отката импорта |
| `green_control_demo.sqlite3` | Отдельный SQLite-образ с разобранными учебными карточками |
| `evaluation.md`, `evaluation.json` | Автоматический отчёт и машинные метрики последнего опубликованного локального прогона |

## Поля выгрузки

| Поле | Значение |
| --- | --- |
| `case_id`, `case_type` | Технический ID и код категории `standard` или `emergency` |
| `application_date`, `issued_date`, `predecision_date` | Даты заявления, выдачи, предварительного решения, ISO ГГГГ-ММ-ДД |
| `documents`, `documents_complete` | Отмеченные документы через `|` и состояние комплекта `yes` или `unknown` |
| `accrued_amount`, `paid_amount` | Начисленная и уплаченная суммы, пустое поле означает неизвестность |
| `exemption_code`, `exemption_proof` | Код освобождения и состояние подтверждения `yes`, `no` или `unknown` |
| `finance_mode`, `payment_note` | Финансовый сценарий и необязательное пояснение к оплате |
| `comment` | Описание синтетического сценария на русском |

Все сведения придуманы для проверки модели. Генератор по умолчанию перебирает авторские сценарии циклически, а seed задаёт даты и суммы. Эталон задан отдельно в сценариях. Для того же seed, размера и даты среза строки и метки повторяются. Метаданные контейнера XLSX и время расчётов в SQLite могут различаться.

Из корня проекта запустите `python -m scripts.generate_synthetic --seed 20261120 --count 200 --reference-date 2026-11-20 --output data/another_demo --sqlite`. Для оценки выполните `python -m scripts.evaluate_synthetic --data data/another_demo --output data/another_demo`. Флаг `--sqlite` создаёт образ в новом каталоге и проверяет, что целевой файл отсутствует.

Для показа запустите приложение с отдельной копией образа через `GREEN_CONTROL_DB`. Выгрузки можно импортировать через «Импорт из ИС». Для сброса демонстрации используйте свежую копию образа. Рабочая SQLite по умолчанию находится в `data/green_control.sqlite3` и хранится отдельно.
