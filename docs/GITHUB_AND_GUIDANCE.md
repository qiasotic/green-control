# Подключение к GitHub и объяснение проверок

## Получить данные из GitHub

Откройте **Импорт из ИС → Подключение к GitHub**.

1. Вставьте HTTPS-адрес публичного репозитория. Можно вставить ссылку на конкретный CSV или XLSX. Если имя ветки содержит косую черту, используйте постоянную ссылку на коммит.
2. Нажмите **Проверить подключение**. Для ссылки на репозиторий увидите доступные файлы основной ветки. При длинном списке отфильтруйте его по пути. Выберите файл и нажмите **Предпросмотр выбранного файла**.
3. Проверьте размер, количество строк и колонок, первые десять строк. В панели **Сопоставление колонок** задайте номер и категорию дела. Можно сопоставить и остальные поля. Для категории подходят «Общая процедура», «Аварийные работы» или совместимые коды исходной выгрузки. Даты можно вводить в формате `ДД.ММ.ГГГГ`.
4. Нажмите **Проверить данные**. Сверьте новые, совпадающие, изменённые и ошибочные записи. В отдельной таблице видны дела и поля, которые изменятся. Если есть ошибка в строке, исправьте файл у источника и получите новую версию.
5. Нажмите **Импортировать данные**. Если файл меняет существующие дела, потребуется отдельное подтверждение. Несопоставленные поля существующего дела сохраняются. Прежние редакции, расчёты и заключения остаются в истории.
6. Откройте **Перейти к анализу** для первой обработанной карточки либо **Открыть реестр дел** для просмотра остальных.

Для обновления откройте **История источников и обновления**, выберите сохранённый файл и нажмите **Проверить обновления**. Новая версия сначала попадёт в предпросмотр. Если версия прежняя, дополнительные записи в БД не создаются. По ссылке на коммит проверяется зафиксированная версия. Для последующих обновлений используйте ссылку на ветку. Импорт допускает CSV/XLSX до 10 МБ и 5 000 строк. У поиска GitHub может быть неполный результат для большого репозитория. В таком случае используйте прямую ссылку на файл.

## Проследить результат проверки

- На главном экране видна цепочка от исходных данных к анализу, сигналу и рекомендации. Отсюда можно открыть создание дела или импорт. Для возврата нажмите «Зелёный контроль» в левой панели.
- В карточке дела блок **Как получен результат** показывает один конкретный пример с данными этой карточки. Ниже все три проверки организованы одинаково. Видны использованные поля, условие, результат, рекомендация и зафиксированное действие.
- **Уточнить сведения** открывает финансовые поля, документы или даты. После сохранения карточки новая редакция рассчитывается автоматически. В неизменённой карточке доступен **Перезапустить анализ**.
- Заключение оформляется во вкладке **Рассмотрение и заключение**. Даты прежних редакций, результаты и действия доступны во вкладке **История**. Модельные условия и происхождение контрольного набора раскрыты в разделе **Настройки**.

## Включить подсказки

Ползунок **Подсказки по работе с системой** показывает пояснения рядом с группами полей и действий. В форме поясняется, что вводить и когда оставлять поле пустым. В карточке пояснения помогают различить исходные сведения, сравнение, результат и действия специалиста. В GitHub подсказки сопровождают подключение, предпросмотр, сопоставление колонок и подтверждение импорта. Включение и отключение подсказок сохраняет несохранённые значения формы в текущей сессии.

## Какие файлы изменились

- `app.py`, `ui/components.py`, `ui/casework.py` — навигация, цепочка на обзоре, карточка с пояснениями, переходы, фильтры и отображение дат.
- `ui/training.py`, `ui/github.py` — обучение и пошаговый интерфейс импорта.
- `core/presentation.py`, `core/models.py`, `core/reports.py`, `core/analytics.py`, `core/guidance.py` — русские подписи, даты, исходные значения и экспорт.
- `core/github_connector.py`, `core/importer.py`, `core/storage.py` — получение данных из публичных репозиториев, разбор CSV/XLSX, проверка сопоставления и транзакционная история источников.
- `tests/test_github_and_explanation.py` — импорт, ошибки сети, повторная загрузка, объяснения и обучение. Существующие тесты обновлены там, где намеренно изменилось отображение или появился ввод российской даты.

## Экраны для визуальной приёмки

1. **Рабочее место** с цепочкой, кнопками создания и загрузки.
2. **Импорт из ИС → Подключение к GitHub** с проверенным репозиторием и выбранным файлом.
3. **Предварительная проверка** с первыми десятью строками, сопоставлением и итогами проверки.
4. **Анализ и проверка** с раскрытым отклонением. Для автономного показа можно загрузить контрольное дело № 002 из вкладки файлового импорта.
5. Включите **Подсказки по работе с системой** и проверьте, что пояснения меняются при переходе между группами полей.
6. В карточке раскройте рекомендации и действие специалиста, затем откройте **Рассмотрение и заключение**.
